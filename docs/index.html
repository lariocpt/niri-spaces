What it does A file, not a plugin

A space is a small text file that describes a workspace: an app to launch, the workspace it belongs on, and how to size it once it appears. niri-spaces load reads the file, launches each app, waits for its window, moves it onto the right workspace and sets the column widths — then steps aside. Layout loading exits when complete. Optional terminal pairing runs a Python watcher when enabled.

It talks to niri through niri msg, the same command you could type yourself. If you can drive niri msg action move-window-to-workspace, you understand every move niri-spaces makes.

Declarative

A layout is a file you commit, not a sequence of keypresses you repeat every session.

Portable

Spaces reference $TERMINAL / $BROWSER; the right app is resolved on each machine, so one file works across hosts.

Just Bash

A single CLI script plus a Python splash. Optional 50/50 terminal pairing is configured in settings.json and is off by default.

Transparent

Every action is a niri msg call. When something looks wrong you can replay it by hand.

Install one command

The installer downloads the pinned release, checks its SHA-256 before running anything, and installs three executables in ~/.local/bin and copies settings, example spaces and an autostart file into ~/.config/niri-spaces. Existing configuration is kept.

curl -fsSL https://lariocpt.github.io/niri-spaces/install.sh | sh

Read before you run it: the installer source.

After installing, load a space and you have a layout:

niri-spaces load default
The installer prints the niri keybind you can add to your config to open the picker — it does not edit your config for you. You decide where the keys go.

Commands niri-spaces --help

Commands:

niri-spaces — declarative workspace layout manager for niri.

  niri-spaces load <name> [args...]   load spaces/<name>.space (or templates/<name>.space with $1..$9 substituted)
  niri-spaces start                   run every `load ...` line in ~/.config/niri-spaces/autostart
  niri-spaces menu                    pick a space interactively (fuzzel if available, else terminal)
  niri-spaces list                    list available spaces and templates
  niri-spaces terminal-pairs [--check] run the optional 50/50 terminal watcher

Space files live in ~/.config/niri-spaces/spaces/ and templates/.

Layout file format (.space) — parsing ported from niri-wspaces-loader:
  @workspace <name-or-index>
  <app_id> | <launch command> [| <env vars> [| <capture var>]]
  @action <shell command>            # may use captured window-id vars
Lines starting with # and blank lines are ignored.

This block is niri-spaces --help verbatim; a build check fails the page if they ever drift apart.

The .space format workspace line, app lines, actions

A file is read top to bottom. A @workspace line sets the current workspace; every app line after it lands there.

LineMeaning
@workspace <name-or-index>All following app lines target this workspace (a name or a number).
app_id | command | env | captureLaunch command, then find the window whose app id matches app_id and move it to the current workspace. The last two fields are optional: env is exported for the launch, capture names a variable that receives the window id.
@action <shell>Run a shell command, e.g. to focus a captured window and size its column.
# …A comment; blank lines are ignored too.
Fields split on |, so a launch command must not contain a literal pipe — no inline || fallbacks. Export $TERMINAL / $BROWSER instead.

An example space spaces/default.space

Here is the space the installer ships as the fallback. It opens a terminal and a browser side by side on a single workspace, capturing each window id so the actions can size them 50/50.

# Single workspace — terminal + browser
#
# Portable: $TERMINAL / $BROWSER are resolved by niri-spaces at load time.
@workspace default

# Left: terminal
$TERMINAL_APPID | $TERMINAL | | terminal_id

# Right: browser
$BROWSER_APPID | $BROWSER | | browser_id

# 50/50 side by side
@action [ -n "${terminal_id:-}" ] && niri msg action focus-window --id "$terminal_id" && niri msg action set-column-width "50%"
@action [ -n "${browser_id:-}" ] && niri msg action focus-window --id "$browser_id" && niri msg action set-column-width "50%"

Run it with niri-spaces load default.

Requirements and honesty

  • niri — niri-spaces drives the compositor only through niri msg. It needs a running niri session.
  • Wayland — it is a niri tool; it does not manage X11 or other compositors.
  • jq and bash — the CLI is bash and needs jq; the splash is Python 3.

This is not a session manager and does not restore windows you closed. It launches the apps a space names and places them — start from there.
